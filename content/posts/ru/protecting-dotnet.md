## Интро

Сегодня мы с вами разберём ситуации с защитой ПО на архитектуре .NET.

На данный момент (2025.11.09) в экосистеме .NET остаётся прежняя проблема — возможность декомпилировать бинарник практически до уровня исходного кода* (с учётом некоторых ограничений).

С этой проблемой сталкиваются многие разработчики, которые выводят .NET-проект в публичную среду и имеют коммерческие отношения. Зачастую проблема затрагивает лицензирование ПО, иногда — защиту интеллектуальной собственности (кода) от просмотра и модификации.

Собственно, возникает вопрос: *раз .NET «дырявый» — как победить данную проблему?*

И тут вступают разные способы защиты ПО от вскрытия и модификации:

1. Обфускаторы кода
2. Кастомные сборки .NET (`dotnet publish` с модифицированной средой .NET)
3. Виртуализаторы кода (ВМ для IL-опкодов)
4. Рекомпиляторы .NET (IL-стек) в машинный код (x86/x64, Arm64): AOT-компилятор (ранее известный как Mono AOT), il2cpp

Давайте рассмотрим в теории, как работают данные процессы.

## 1. Обфускация кода

Это процесс, который перед компиляцией (или сразу после неё) редактирует проект: меняет названия переменных, их положение в коде, добавляет «мусорный» и бессмысленный код, а также специальный код и атрибуты, которые мешают программам дизассемблирования.

**Пример обфускации кода**

До:

```csharp
public bool CheckLicense(string key)
{
    return key.Length == 16 && key.StartsWith("GM-");
}
```

После:

```csharp
public bool \u0002(string \u0003)
{
    int num = 1;
    while (true)
    {
        switch (num ^ 0x5A3)
        {
            case 0x5A2: if (\u0003.Length != (0x1F >> 1) + 1) return false; num = 0x5A1; break;
            case 0x5A0: return \u0003.StartsWith(\u0005.\u0002(0x3C));
            default: num = 0x5A3; break;
        }
    }
}
```

А теперь рассмотрим плюсы данного решения:

1. **Гарантия работы** — изменения вносятся на этапе, после которого код проходит все проверки компиляции. Скомпилированный бинарник гарантированно будет работать.
2. **Простота использования** — не нужно глубоких знаний: подключил и используй.

Ну и к минусам:

1. **Нестойкая защита** — обфускация лишь усложняет реверс-инжиниринг. Если использовать публичный обфускатор, высок шанс, что его можно деобфусцировать, например, популярной утилитой `de4dot` и её многочисленными форками, которые комьюнити адаптирует под определённые сценарии.

| Плюсы | Минусы |
| --- | --- |
| Гарантия работы | Нестойкая защита |
| Простота использования | |
