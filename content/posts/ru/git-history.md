## У изменения есть причина

Дифф показывает, какие строки изменились. Сообщение коммита может объяснить, почему это произошло. Когда оно повторяет только очевидное из кода, история теряет часть своей ценности.

Полезный коммит отвечает на конкретный вопрос будущего читателя: какую проблему решало это изменение?

## Один законченный шаг

Старайтесь собирать в коммит изменения, которые можно объяснить одной мыслью. Это не всегда один файл и не обязательно маленький дифф. Главное — связность причины.

Если переименование переменных смешалось с исправлением поведения, читателю придётся отделять одно от другого самостоятельно.

## Проверить перед сохранением

```bash
git status --short
git diff
git diff --staged
```

Последняя команда показывает именно то, что войдёт в коммит. Это хороший момент, чтобы заметить случайный лог, локальную настройку или файл, который не относится к задаче.

## Сообщение без лишних слов

Вместо «исправления» лучше назвать наблюдаемую проблему. При необходимости добавьте короткое объяснение в теле сообщения:

```text
Сохранять фильтр при возвращении к списку

Раньше переход из статьи сбрасывал выбранную рубрику.
Теперь список восстанавливает её на время текущей сессии.
```

Так история становится дополнительным слоем документации. Она не заменяет код, но помогает понять условия, в которых принималось решение.
