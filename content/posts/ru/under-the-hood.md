## Одна строка, несколько слоёв

Вызов функции выглядит как простое действие. Мы передаём аргументы, получаем результат и продолжаем работу. Но процессор не знает о функциях в том смысле, в котором о них думает программист.

Чтобы увидеть разницу, достаточно маленькой программы, исходный код которой полностью под нашим контролем.

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(20, 22));
    return 0;
}
```

Здесь нет сложной логики. Именно поэтому пример удобен: детали не теряются за предметной областью.

## Сначала — вопрос

Полезнее начинать исследование с конкретного вопроса, а не с большого дампа. Например: где окажутся аргументы `a` и `b` и как значение вернётся вызывающему коду?

Ответ зависит от архитектуры, соглашения о вызовах, компилятора и оптимизаций. Единой картинки для всех систем не существует.

Для GCC на системе с x86-64 можно получить ассемблерный листинг так:

```bash
gcc -O0 -S -masm=intel example.c -o example.s
```

Флаг `-S` останавливает сборку после генерации ассемблерного текста. `-O0` облегчает сопоставление простого исходника с полученным кодом, хотя не обещает буквального перевода каждой строки.

## Что искать в листинге

Начните с метки `add`. Проследите, откуда берутся входные значения, какая инструкция выполняет сложение и где оказывается результат. В System V AMD64 первые два целочисленных аргумента обычно передаются через регистры `edi` и `esi`, а результат типа `int` — через `eax`.

| На уровне языка | На уровне исполнения |
| --- | --- |
| Аргументы функции | Регистры или стек по соглашению о вызовах |
| Локальные переменные | Регистры, память или полное устранение |
| Возвращаемое значение | Место, определённое соглашением о вызовах |
| Вызов функции | Передача управления, если вызов не устранён |

Самая важная часть исследования — связь между этими слоями, а не запоминание мнемоник.

## Оптимизация меняет картину

Теперь замените `-O0` на `-O2` и сравните два листинга. Компилятор может встроить функцию, вычислить константное выражение заранее или убрать промежуточные значения.

```bash
gcc -O2 -S -masm=intel example.c -o example.optimized.s
diff -u example.s example.optimized.s
```

Поэтому отсутствие ожидаемой инструкции не всегда ошибка наблюдения. Иногда интересующее действие уже произошло на этапе компиляции.

> Хорошая привычка — менять один параметр за раз и записывать, какое наблюдение он изменил.

## Что сохранить после эксперимента

Запишите версию компилятора, архитектуру, флаги и исходник. Без них красивый скриншот листинга быстро превращается в загадку.

Небольшой воспроизводимый пример даёт больше, чем десятки страниц случайного дизассемблированного кода. Он позволяет проверять гипотезы и постепенно строить собственное понимание.
